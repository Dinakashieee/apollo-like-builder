# Architecture
- SignalHire API account balances are validated server-side and displayed separately from workspace reveal wallets; connection badges require a successful provider response, never browser flags.
- SignalHire discovery uses documented top-level Search API filters and persists synchronous profile previews; search previews never imply contact details have been revealed.
- SignalHire waiting states consume synchronous results and use bounded saved-row reads alongside live notifications for asynchronous completion; transport failures clear loading without automatically replaying provider searches.
- Daily work updates use a single-message daily form with server-side AI interpretation, local calendar dates and owner-plus-membership RLS; exact-message deduplication and a service-role-only transactional RPC save summaries/tasks and uniquely matched explicit lead changes together. The daily form is a structured update action, not a threaded AI conversation.
- Daily next-step lines synchronize transactionally to private daily tasks via a database trigger; unchanged task text retains completion, removed lines and deleted updates remove linked tasks, and dashboards filter updates by local work date.
- Public recommendation evidence is checked through a bounded shared scraper; source dates come from publication metadata, system/contact claims require verbatim company-specific evidence, and SignalHire handoffs require review of real provider results before claiming.
- Company email context defaults are shared by both composers and applied per selected lead; personal signatures use user-owned rows with a profile default pointer, retain the legacy profile signature, and sanitize HTML previews.
- Personal dashboard summaries use an authenticated, workspace-membership-gated aggregation scoped to auth.uid(); calendar-to-date boundaries use the user's local timezone and email counts deduplicate latest message status before filtering.
- Email sending breaks are persisted per authenticated user and enforced at enqueue and dispatch; paused outreach remains pending until explicit resume, while authentication and essential system emails continue.
- Landing-page themes use a shared renderer and scoped semantic tokens for identical editor/public output; legacy templates remain supported without rewriting saved content.
- The Landing Pages list reuses the editor preview renderer for a selected saved page, with a local sample when empty, so viewing previews never creates or publishes content.
- Landing color palettes update the existing accent and brand-color fields together; palette swatches use scoped CSS tokens so selection adds no separate persistence path.
- Temporary feature access is isolated from subscription status and metered usage: frontend feature limits and the server lead-quota helper use explicit temporary switches, and landing customization remains authenticated and workspace-membership gated; AI and SignalHire allowances retain their existing enforcement.
- Campaign landing designs import sequence text explicitly; custom-color saves and section reordering use the shared landing-access RPC, while image storage is workspace-member scoped.
- Landing image generation runs in an authenticated edge function with an atomic reservation against the existing monthly AI allowance before inference, preventing concurrent quota bypasses.
- Company signals are generated by the authenticated company-signals edge function and persisted with evidence/status; clients only supply company context, so unsupported scores remain unknown.
- Lead inserts synchronize workspace-deduplicated account records; manual creation, lead imports and SignalHire claims invoke company research after successful saves, avoiding secret-dependent dispatch.
- Company imports and CSV exports use shared company data helpers; CSV exports neutralize formula injection.
- AI brand-color matching reads the company site (Firecrawl scrape, direct fetch fallback) in an authenticated edge function and only returns validated 6-digit hex palettes; client only supplies workspace and URL.
